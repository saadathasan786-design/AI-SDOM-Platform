# Service Business Website Boilerplate

AI-SDOM project baseline for service-business websites.

## Purpose

Provides reusable implementation structure and neutral primitives for generating service-business websites through the AI-SDOM governed project-execution path.

This boilerplate contains no fabricated client facts, credentials, testimonials, reviews, statistics, or claims.

## Intended execution path

1. Project request
2. Requirements discovery
3. Project classification
4. Architecture selection
5. Boilerplate selection
6. Content/configuration population
7. Implementation
8. QA, accessibility, security, SEO, and performance validation
9. Handover

## Placeholder policy

Client-specific information must be supplied through project configuration/content inputs. Examples include:

- `{{BUSINESS_NAME}}`
- `{{BUSINESS_DESCRIPTION}}`
- `{{PRIMARY_SERVICE}}`
- `{{SERVICE_AREAS}}`
- `{{PHONE}}`
- `{{EMAIL}}`
- `{{PRIMARY_CTA}}`

Do not replace unknown values with invented facts.

## Baseline directories

- `assets/` — local static assets and generated project assets
- `components/` — reusable UI components
- `content/` — structured project content and content schema
- `pages/` — page-level composition
- `sections/` — reusable page sections
- `styles/` — design tokens and global styles
- `scripts/` — client-side behavior
- `config/` — project configuration and schema
- `tests/` — baseline validation tests

## Quality baseline

Projects generated from this baseline must be validated for:

- responsive behavior;
- semantic HTML;
- keyboard accessibility;
- visible focus states;
- basic WCAG-aligned accessibility requirements;
- metadata and canonical URL handling;
- heading hierarchy;
- image alternative text;
- asset optimization;
- broken links and navigation;
- JavaScript/runtime errors;
- security-sensitive input handling;
- production build integrity.

This boilerplate is a starting point, not evidence that a generated project has passed these checks.
